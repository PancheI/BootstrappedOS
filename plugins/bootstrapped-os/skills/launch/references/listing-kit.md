# The facts block (and the two pitches)

Write it once from `CLAUDE.md` and the live site. Paste it **byte-identical** on every directory, profile and launch. Same facts everywhere is how an engine decides "this is one entity". Change the block, never one listing.

Rules: every number true today and in `knowledge/numbers.md`; plain words; no quotes or apostrophes if a form strips them; the name field holds the name.

## The block

- **Name:** <exactly as on the site>
- **URL:** <https://yoursite.com>
- **One line (≤60):** <who it's for + the outcome>
- **Short (≤160):** <what it is, for whom, one proof you can source, price>
- **Long (≤500 words):** <who and the problem, in their words> <what it does, one concrete example> <who runs it and the proof> <price, plainly>
- **Founder:** <name> · <story page URL>
- **Founded:** <date> · <city> · <where it serves>
- **Category (2-3 options), tags (5-8)**
- **Logo:** <URL, 512×512 PNG> · **Social image:** <URL, 1200×630 PNG>
- **What's different (≤140)**
- **Maker comment (≤120 words):** why you built it, who it's for, one question you want answered.

## An example (invented business)

- **Name:** Tidyshelf
- **One line (52):** Stock counts for small shops, done in 10 minutes a week
- **Short:** A stock-count app for independent shops with one or two staff. Scan the shelf with your phone, see what to reorder. Built by a former shop owner. $15 a month.
- **Proof:** one fact the founder can source today, for example "used weekly by 40 shops" if `numbers.md` says 40.

What to learn from writing it:
- The proof is a sourced fact, not a feature list. Pick the one number you can show today.
- Name what the number counts. Checkouts opened, payments completed and paying customers are three different numbers; say which one.
- When a number changes, change it everywhere the same day. An old number on one profile makes engines doubt the rest.
- Count only what's true today. No member counts that include friends, no "free to start" once it isn't.

## Before each submit
- The name box holds the name, not the tagline (a prefilled form once swapped them and the listing went live wrong).
- Same name and URL as every other listing.
- The link carries its UTM: `?utm_source=<site>&utm_medium=directory`.
- The profile URL goes into `sameAs` on the site once it's live.

## Podcast or interview pitch (≈70 words)

> Subject: [the result, in one sourced number]
>
> Hi [name], I'm [first name]. [The problem, one line: what wasn't working.] [The turn: what you changed.] [The result, with the number and what it counts.] The full story: [link]. Happy to share exactly what I changed, with numbers, if it fits [show].
>
> [First name]

Shape to copy: the subject is the result; line 1 is the problem; then the turn, the proof link, the offer to share numbers. No "I'd love to be on your show". The author's own pitch, built this way, got him a case study on a big founder community.

## Roundup note (≈50 words)

> Hi, I read your list of [category]. [Product] ([URL]) could fit: it is for [who], [what it does in one line], [price]. [One sourced proof.] Happy to send a one-line description if useful. [First name]

On a dev.to list, comment instead of pitching, with a disclosure: "Good list. One I would add for [who]: [name]. [What it does, one line.] (I run it, so take that into account.)"
